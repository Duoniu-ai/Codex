# SiteIntel AI 可发现性与数据权威性战略

> 目标：让 SiteIntel 成为搜索引擎与 AI 系统容易发现、理解、验证和引用的可信公开数据源。

## 1. 核心判断

未来互联网入口会越来越 AI 化。

因此 SiteIntel 不能只考虑传统 SEO，还应考虑：

**AI Discoverability + Data Authority**

SEO 面向搜索引擎；AI 可发现性面向 AI；数据权威性是长期护城河。

## 2. 不应该追求的目标

不是简单追求：

> “让所有 AI 爬更多 SiteIntel 页面。”

更重要的是：

> 当用户向 AI 提问某类互联网实体、网站、技术或企业公开信息时，SiteIntel 有机会成为可引用、可验证的来源之一。

## 3. 公开层与商业层

公开页面可以承担：

- SEO
- AI Discoverability
- 品牌曝光
- 数据样例
- 基础事实

登录 / 企业 / API 层可以承担：

- 深度历史
- 批量分析
- 监控
- 私有分析
- 高级情报
- 企业 API

因此不建议为了防止数据被 AI 看到而把整个网站关闭抓取。

## 4. 技术基础

后续逐步完善：

- 清晰、稳定的 URL
- 规范化 canonical
- Schema.org / JSON-LD 等结构化数据
- 实体页面
- 机器可读的事实字段
- 来源与证据
- 更新时间
- 数据版本
- 清晰的 robots 策略
- AI / crawler 访问策略
- 开发者文档
- 有边界的公开 API

## 5. AI 引用价值的基础

AI 更容易理解和信任：

- 清晰的实体
- 明确的数据来源
- 明确的观察时间
- 可验证的证据
- 稳定的 URL
- 一致的数据定义
- 持续更新记录

因此数据结构和证据链本身就是 AI 可发现性的一部分。

## 6. 分层抓取策略

原则上可以采用：

### Public

允许搜索引擎和合规 AI 抓取基础公开信息。

### Deep / Commercial

通过登录、企业套餐或 API 控制访问。

### Private

用户自己的 Search / Investigation / Report 等内容必须严格隔离，不允许成为其他用户或公共 AI 抓取对象。

## 7. 长期路线

### 2.x

先完善实体模型、URL、元数据、证据链和公共页面质量。

### 后续阶段

逐步建立结构化数据、机器可读接口和开发者文档。

### 更长期

根据 AI 生态变化适配不同平台，但避免绑定单一 AI 公司。

## 8. 最终目标

让 SiteIntel 的公开数据具备：

**可发现、可理解、可验证、可引用、可调用。**

最终真正的资产不是“某个 AI 是否引用了某一页”，而是 SiteIntel 是否成为互联网实体数据的可信来源。
