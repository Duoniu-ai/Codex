# 外部参考：企业数据纠错、删除与认领机制——名录集

## 1. 参考对象

名录集旗下“新工商名录”提供企业公开信息查询，并设置独立的“数据纠错与删除”入口。其公开说明称，企业信息主要来源于国家企业信用信息公示系统，并尽量与官方公示信息保持一致。

## 2. 值得 SiteIntel 参考的机制

### 2.1 数据纠错入口

平台允许企业或相关人员针对展示错误提交更新、删除或修改申请，并支持在企业详情页面直接发起申请。

### 2.2 证据要求

对于人工纠错，平台要求提供企业名称以及能够证明数据错误的相关佐证；邮件渠道还要求提供页面链接、修改内容和证明材料。

### 2.3 官方源优先原则

平台明确区分“官方登记变更”和“平台展示同步”：如果企业尚未在国家企业信用信息公示系统完成官方变更，平台原则上无法仅凭用户要求修改工商核心信息。

这一点对 SiteIntel 的 Evidence Chain 很有参考价值：**用户提交的信息不能天然覆盖原始来源事实，应区分 Source Fact、Claim、Verification 和 Platform Correction。**

### 2.4 企业认领机制

平台提供企业认领入口。认领审核通过后，企业可以自行编辑部分联系信息、产品信息等内容，同时需要对提交内容的真实性承担责任。

这可以作为 SiteIntel 后续“企业实体认领 / Entity Claim”功能的参考模型。

## 3. 对 SiteIntel 2.x 的启发

建议未来的数据治理模型至少区分：

- `Source Fact`：来自官方或可信来源的原始事实
- `Observed Fact`：SiteIntel 自己观测到的事实
- `User Claim`：企业/用户主动提交的信息
- `Correction Request`：纠错请求
- `Verification Evidence`：证明材料
- `Verification Status`：待审核 / 已验证 / 驳回 / 部分验证
- `Correction History`：纠错历史
- `Deletion Request`：删除请求
- `Entity Claim`：实体认领状态
- `Last Verified At`：最近验证时间
- `Source URL`：事实来源

## 4. 建议的产品原则

SiteIntel 不应简单提供“修改数据库”的入口，而应建立**可追溯的数据纠错工作流**：

`用户发现问题 → 提交纠错 → 提供证据 → 关联具体事实 → 审核 → 记录处理结果 → 更新展示 → 保留历史审计记录`

对于删除请求，应进一步区分：

1. 数据本身错误；
2. 官方源已经删除/变更；
3. 用户要求删除但官方公开源仍存在；
4. 涉及个人信息、敏感信息或其他法律合规问题；
5. 平台缓存/历史记录是否需要同步处理。

## 5. 与 SiteIntel 商业化的关系

企业认领不仅是数据治理能力，也可能成为未来商业化入口：

- 企业认领页面
- 企业资料完善
- 官方联系方式维护
- 企业网站/APP/小程序关联
- 品牌与 Logo 资料维护
- 企业技术栈补充
- 企业情报订阅
- 变更监控
- 企业数据 API

但需要明确：**认领后的企业自提交内容不能直接与第三方独立观测事实混为一谈。** 页面展示应标注信息来源和验证状态。

## 6. 风险与合规提醒

该页面本身仅作为产品机制参考，不构成对中国企业信息处理、个人信息保护、删除请求、数据授权或商业数据合规性的法律判断。SiteIntel 后续真正上线类似能力时，应针对数据来源、个人信息、企业公开信息、删除/更正请求、证据留存和审计机制进行专项合规设计。
