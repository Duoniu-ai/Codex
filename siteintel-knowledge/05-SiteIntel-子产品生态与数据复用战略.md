# SiteIntel 子产品生态与数据复用战略

> 核心思想：未来建立多个垂直子站，但共享同一个互联网数据底座。

## 1. 子产品不是独立数据孤岛

未来可能建设：

- Logo / Brand 资源站
- Icon / Favicon 资源站
- Technology 技术目录
- Product / SaaS 目录
- Website / Inspiration 目录
- 企业数据库
- 网站群 / 企业关系数据库
- 行业情报站
- 其他具有明确市场价值的垂直数据产品

这些站点不应各自重新抓取互联网。

应尽量由 SiteIntel 数据底座提供基础数据。

## 2. 复用关系

例如一个网站被 SiteIntel 发现后，可以同时贡献：

- Website 数据
- Company 数据
- Brand 数据
- Logo
- Favicon
- Technology
- IP / ASN
- CDN
- Screenshot
- Open Graph image
- Product
- Industry
- Historical observations

因此一次采集可以产生多个产品的数据价值。

## 3. Logo 子产品

可复用：

- Brand name
- Company name
- Logo URL
- Logo variants
- Logo history
- Favicon
- Brand color
- Website
- Product relationship
- Source
- First seen / last seen

## 4. Icon / Favicon 子产品

可复用：

- favicon
- icon URL
- website
- brand
- product
- dimensions
- format
- first seen
- last seen
- source

## 5. Technology 子产品

可复用：

- Technology
- Category
- Version observation
- Website adoption
- Industry distribution
- Country / region distribution
- First seen / last seen
- Historical adoption

这类数据有机会发展成独立技术目录或技术情报产品。

## 6. 企业 / 产品子产品

可复用：

- Organization
- Brand
- Product
- Website
- Public descriptions
- Industry
- Geographic signals
- Technology
- Recruitment signals
- Historical changes

## 7. 子产品选择标准

不是什么数据都值得做一个站。

优先选择：

1. 用户需求明确
2. 搜索 / AI 查询需求明确
3. 数据可以规模化获取
4. 数据可以持续更新
5. 数据存在历史价值
6. 数据可以形成结构化目录
7. 有广告、会员、API 或企业服务等商业模式
8. 可以复用 SiteIntel 已有数据

## 8. 统一数据底座

长期理想结构：

`Internet Observation`

→ `Website`

→ `Infrastructure`

→ `Technology`

→ `Organization`

→ `Brand`

→ `Product`

→ `Relationship`

→ `Historical Event`

→ `Intelligence Signal`

不同子站只是针对不同实体或数据视图进行产品化。

## 9. 最大的长期价值

如果未来做出多个垂直站点，真正重要的不是站点数量，而是：

**同一套数据采集能够同时支撑多个产品。**

这样可以降低边际成本，并让每一个新子产品反过来提高整个数据网络的价值。

## 10. 长期愿景

SiteIntel 主站负责不断发现和理解互联网；子产品负责把不同数据资产包装成用户容易理解、搜索、使用和付费的垂直产品。

因此未来可能形成：

**一个数据底座 + 一个核心情报平台 + 多个垂直数据产品。**
