SiteIntel 2.0 Phase 3B.3 — 报告页阅读路径与首屏价值精修
执行时间：2026-08-16 · 范围：仅 /website/[domain] 及其局部展示组件/i18n/纯展示层 helper · **不是删数据，是改变曝光层级**

## 1. 当前页面问题（3B/3B.1/3B.2 后的遗留）

① 头部 meta 行（首次发现/最近更新/调查次数/最新运行）与一句话结论同层竞争，dashboard 感残留；② 首屏指标 chips 最多达 6-7 个（信息密度超标）；③ 网络与基础设施 9 张卡全部同级铺开，专业字段（DNS 服务商/证书/HTTP 安全头）与核心信息同等权重；④ 关联区直接进入表格+图谱，缺少「先结论后明细」的摘要层；⑤ 洞察排序逻辑内联在页面中不可测试。

## 2. 首屏前后对比

| 前（3B.1/3B.2） | 后（3B.3） |
|---|---|
| 面包屑 → H1 + meta 行（4 项时间/状态）→ 结论面板（结论 + 最多 7 chips + CTA） | 面包屑 → **H1（仅状态点）** → 结论面板（结论 + **≤4 chips** + CTA） |
| 首次发现/最近更新在头部抢占注意力 | **移入「网站概览」卡**（数据保留，层级降级） |
| 调查次数/最新运行在头部 | 移入概览卡内「分析记录」折叠（原 3B.1 已折叠） |

**首屏最终回答三问**（全部真实数据）：① 这是什么网站（H1 + 结论句）② 现在怎么样（状态 chip + 结论句中的状态分句）③ 最近有没有值得关注的变化（30 天变化 / 重点关注 chip，二选一由真实数据决定——重点关注可用时替代变化数）。

## 3. 信息层级前后对比

| 层级 | 前 | 后 |
|---|---|---|
| 第一屏指标数 | 最多 7 | **≤4**（状态 / 主要技术 ×1 / 网络服务 / 变化或关注二选一）——`pickFirstScreenMetrics` 纯函数控制 |
| 它如何运行 | 9 卡同级 | **核心 4 卡默认展开**（IP / 网络位置 / 托管 / CDN）+ **5 卡折叠**（DNS 服务商/TLS/邮箱/域名注册/HTTP 安全头 + DNS 记录表）入「查看完整基础设施信息」 |

| 值得关注 | 强调容器（3B.1） | 保持 + 排序逻辑提取为可测试纯函数 `sortInsightsByRelevance` |
| 关联探索 | 表格 + 图谱折叠 | **新增摘要行**：「这个网站与 N 个公开对象存在关联：X 个共享基础设施、Y 个共享技术」→ 表格 → 图谱（第二层，保持折叠） |
| 深入数据 | 四子块折叠（3B.1） | 保持 |

## 4. 哪些数据只是下沉而非删除

**全部**。9 张基础设施卡、DNS 记录表、meta 时间信息、分析记录、图谱、深入数据四子块——全部保留且可展开；仅默认曝光层级改变。生产验证：折叠元素总数 17+，逐一可展开。

## 5. 最近变化处理

保持 3B.1/3B.2 结构：Top 3 强调卡（severity 排序、聚合、具体 diff、证据跳转）+「查看全部变化（N）」折叠。本阶段未改动（已达标）。

## 6. 值得关注处理

保持 3B/3B.2 结构（结论→为什么→证据，无 slug 无 rule ID）+ 排序逻辑迁移至 `sortInsightsByRelevance`（重要度→证据丰富度→置信度，纯函数可测试）。**与「最近发生了什么」零重复**：变化区只渲染 Event（发生了什么），值得关注区只渲染 Insight（为什么值得关注）——两个区块数据源不同、回答的问题不同。

## 7. 关联处理

摘要行（`buildConnectionSummary` 按 via.entityType 分类：ip/asn/ssl_certificate/provider → 共享基础设施；technology → 共享技术；其他 → 其他关联）→ 相关网站表格（强证据）→「查看关联图谱」（折叠，第二层）。duoniu.cc/baidu.com 实测「与 10 个公开对象存在关联」摘要正确渲染；无关联站点不渲染空摘要（connectionSummaryText 返回 null）。

## 8. 深入数据处理

保持 3B.1 的四子块折叠（健康度/行动路线/搜索数据/原始检测记录）+ 导出按钮可见。本阶段未改动。

## 9. 移动端处理

- 首屏高度压缩：头部 meta 行移除（移动端少 2 行）
- 结论面板 flex-wrap、chips 换行、Top 3 卡 `lg:grid-cols-3`（移动端单列堆叠）、核心 4 卡网格 `sm:grid-cols-2 lg:grid-cols-3`（移动端单列）——响应式类实测存在，无固定宽度新增
- 折叠机制本身移动端友好（无 JS 依赖）

## 15. 已知限制

- 关联摘要的分类基于 via.entityType 启发式（共享基础设施/技术/其他三桶），对同时含多种关联的站点按优先级计入单桶（基础设施>技术>其他）——摘要用途下可接受。
- wordpress.org 当前无 related 记录（语料库规模所致），摘要行自然缺省；随 Discovery 语料增长自动出现。
- 移动端验证为结构层（响应式类检查 + 折叠机制），未做真机截图级验证。
